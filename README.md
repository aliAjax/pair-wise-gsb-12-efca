# 车辆调度小工具

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Naive UI
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 合并逻辑自测：`npm run test:merge`

## 离线调度合并

调度员离线派车、重连回传后，车辆占用、司机占用、区域容量、任务版本容易对不上。
本项目在 `src/dispatch/` 中实现纯函数合并引擎，**调度台、核对区、导出摘要共用同一份合并结果**：

| 需求 | 实现 |
| --- | --- |
| 每笔派车记录留痕发起时刻、车辆、司机、任务版本 | `DispatchOp`（`src/dispatch/types.ts`），`uploadedAt` 仅展示，不参与判定 |
| 同一车辆同一班次只留一条有效占用 | 按 `车辆|班次` 分组，以**发起时刻**最晚一笔为准；最晚为取消则整组作废 |
| 按区域容量排队，超出待核对 | 按 `区域|班次` 容量先到先得，超出进入队列并生成核对项；区域未配置容量时无法判定，留待核对 |
| 同车司机被多车占用 | 同一司机同一班次只保留发起最早的一笔，其余进入核对区 |
| 多设备改同一任务 | 按**发起时刻**取有效版本，不看上传顺序；同刻不同内容无法判定，回退基础版本并留待人工裁定 |
| 引用过期任务版本 | 任务版本落后且有效版本区域已变时占用不生效，进入核对区 |
| 写入失败保留本地批次，修正后重试 | 批次持久化在 localStorage，失败标记 `failed` 且原样保留；可就地修正记录后重试写入 |
| 冲突无法判定 | 统一进入核对区；人工结论按稳定 reviewId 持久化，合并结果随之复算 |
| 三方共用结果 | `mergeDispatch()` 是唯一数据源（`src/dispatch/merge.ts`），三个视图 + CSV/文本导出都消费它 |

### 页面

- **调度台**：在线/离线与服务端故障开关、本地批次写入与失败重试、有效占用、区域容量排队、任务有效版本
- **核对区**：待核对/已裁定，支持超容放行、驳回、改派区域、任务同刻冲突裁定、备注留痕、撤销重核
- **导出摘要**：汇总指标、文本摘要（可复制）、有效占用 CSV、核对清单 CSV、取消/被取代凭据

### 预置演示场景（`src/dispatch/seed.ts`）

同车同班多笔派车、晚发起取消、同司机跨车占用、区域超容、区域未配容量、多设备改任务（含上传顺序与发起时刻相反）、同刻冲突、过期任务版本、写入失败批次 B-004、待上传离线批次 B-005。
点击"恢复演示数据"可随时重置。
