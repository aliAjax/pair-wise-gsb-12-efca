# 车辆调度小工具 · 离线派车合并台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Naive UI
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 测试：`npm test`（合并引擎 15 条 + store 4 条 + SSR 渲染冒烟 2 条，共 21 条）

## 解决的问题

调度员离线派车，重连后车辆占用、司机占用、区域容量、任务版本对不上。
本工具按以下规则做确定性合并，数据默认保存在浏览器 localStorage。

### 合并规则（`src/merge/offlineMerge.ts`，纯函数）

1. **每笔记录留痕**：发起时刻 `issuedAt`、车辆、司机、任务版本 `taskVersion`、来源设备、上传时刻都参与计算；
   仲裁**只按发起时刻**，上传时刻仅在完全同刻同内容时兜底，绝不会因先上传而判赢。
2. **同一车辆同一班次只保留一条有效占用**：发起时刻最新者生效；同刻同内容判为重复派车自动去重；
   同刻但内容不同 → 先后无法判定，双方进**核对区**。
3. **司机占用**：同一司机同一班次被多辆车占用且任务不同 → 双方待核对，可在核对区电话核实后放行。
4. **任务版本仲裁**：不同设备编辑同一任务时取发起时刻最新的版本；同刻同版本但内容不一致 → 双方待核对，
   不会只按上传顺序覆盖。
5. **区域容量排队**：按「区域 + 班次」统计，容量内有效；容量满后按发起时刻先后排队（排队上限可配）；
   超出排队上限 → 待核对。已确认的历史占用先占位。
6. **幂等与重试**：记录带客户端幂等 id，同一批次重传只计一次；重试内容与已确认记录不一致时双方并列待核对。

### 失败保留与修正重试（`src/store/dispatch.ts`）

- 派车 / 编辑先写本地 outbox 批次（localStorage 持久化），离线不丢单。
- 模拟服务端写入失败时，**批次原样保留**并累计 `retryCount` 与错误信息；修正冲突或关闭模拟失败后一键重试。
- 同步成功只把「有效 / 排队」记录入库；待核对、已失效记录随批次保留到核对区处理。
- 核对区支持：核实放行（强制确认，容量规则仍执行）、修正后以新版本重提、作废；
  也可调整区域容量 / 排队上限后立即重算。

### 三端共用结果

调度台列表、核对区、导出摘要（CSV 明细 / TXT 摘要）全部消费同一个 Pinia getter
`store.mergeResult`（由纯函数 `mergeDispatch` 算出），三处数字永远对得齐。

顶部「装载离线重连演示」可一键构造上传顺序被打乱的双设备离线批次，覆盖：
车辆重复派车去重、司机双占、多设备同任务编辑冲突、区域容量排队。
